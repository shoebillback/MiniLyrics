# 0.6.15 整窗移动时的帧唤醒

原生移动由 DefWindowProc 的系统消息循环接管，外层 App::run 暂停执行，原有等待句柄的帧唤醒也随之中断。新增仅在 WM_ENTERSIZEMOVE 至 WM_EXITSIZEMOVE 之间注册的等待转发，使用同一个高精度、按截止时间调度的计时器。回调只投递消息，更新和 Direct2D 绘制仍在界面线程完成；松手或销毁时等待回调结束并注销，旧消息通过序号失效。回退路径保留原有 WM_TIMER。

只运行 moving 专项三个场景，以独立离屏窗口执行生产窗口过程，在移动状态中仅分派窗口消息，不消费外层等待句柄，同时多次改变窗口位置。旧版在 512.9 ms 内绘制 0 帧；修复后的逐字歌词与 GPU 背景在 509.3 ms 内各绘制/生成 30 帧，请求均为 60 FPS。移动期间未重建歌词排版、窗口绘制目标或背景位图。松手后高精度句柄恢复，残留消息被忽略；暂停移动 150 ms 未触发绘制或背景生成，销毁时等待注册被清理。结果在 work/native-moving-before-0.6.15 与 work/native-moving-0.6.15。

此结果验证调度中断与修复，不代表真实网易云拖动的鼠标延迟、显示器呈现帧率或 CPU/GPU 占用测量。正常播放与移动时维持相同目标帧率，未提高渲染分辨率或新增永久轮询；移动期间新增到期消息投递。依据：[WM_ENTERSIZEMOVE](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-entersizemove)、[RegisterWaitForSingleObject](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-registerwaitforsingleobject)、[UnregisterWaitEx](https://learn.microsoft.com/en-us/windows/win32/api/threadpoollegacyapiset/nf-threadpoollegacyapiset-unregisterwaitex)。以下为历史记录。

# 0.6.13 混合 DPI 窗口初始化与跨屏

# 0.6.11 背景帧率与交互缩放

按用户选择，背景默认 30 FPS，支持 10 / 15 / 30 / 45 / 60 FPS。原生缓存检查在每秒 60 次输入采样中，分别只生成 10 / 15 / 30 / 45 / 60 张背景纹理；独立调度周期也与设置对应。背景帧率是生成频率上限，无法保证设备负载高时仍达到所选值；整窗绘制还受歌词和其他交互影响。

旧 0.6.10 窗口过程复现中，WM_SIZE 会先调整 Direct2D 缓冲区，期间没有完成重绘。根据 Microsoft 的 ID2D1HwndRenderTarget::Resize 文档，调整后缓冲区内容未定义。这是闪烁风险，不能单凭该探针声称已测量肉眼闪烁次数。现在将缓冲区调整移入 paint，紧接完整绘制；程序缩放的多条尺寸消息保留合帧，实际鼠标缩放才同步提交尺寸变化对应的完整画面。

交互缩放期间复用背景纹理，暂停其动画时钟，避免每个鼠标尺寸消息因缓存失效而执行模糊、网格及读回。五次实际 Win32 尺寸变化得到五次完整绘制、零次背景生成；松手后生成一次最终尺寸背景并恢复流动。绘图资源与歌词布局继续复用。生成封面在缩放时到达会延后背景更新，保留正常混合过渡；暂停状态的捕获丢失仍完成最终尺寸更新并保持冻结。

两项 JS 配置检查和原生 resize 专项通过。没有重新测量整窗 CPU/GPU 利用率、功耗、完整播放器会话或可见桌面的缩放视频。背景纹理分辨率、模糊和网格算法未调整。前次 10/30 FPS 短测与本轮尺寸复现分别位于工作区 work/background-fps-investigation 和 work/resize-refresh-investigation。官方参考：https://learn.microsoft.com/en-us/windows/win32/api/d2d1/nf-d2d1-id2d1hwndrendertarget-resize(constd2d1_size_u_) 。以下为历史记录。

## 方法与限制

测试脚本为 tests/performance.ps1，两个显示端使用相同的 tests/render-benchmark.cjs。内容依次为空歌词、同一行时间校准、长句滚动完成、暂停、未来歌词开始及截图；默认 30 FPS。测试没有加载网络封面，不含用户正在播放的真实歌曲。两个渲染器依次运行，设置使用独立临时文件。每 250 ms 采样，表格取进程启动约 2 秒后的平均值。

CPU 是短区间的单核百分比，受计时分辨率、GPU 提交和启动/截图阶段影响，波动较大。一次 Direct2D 采样甚至显示 0.00%，只说明该区间没有测出可分辨的 CPU 增量，不代表零 CPU 占用。因此暂不以该短测宣称 CPU 下降百分比。

旧 WPF 二进制是 x86/.NET Framework；新显示端为静态链接的 x64 C++。这是一项整体架构迁移对比，不能将内存收益全部归因于绘图 API。新原生文件约 1.2 MB，比旧 WPF 可执行文件更大，但无 CLR/WPF 运行时依赖。
